# 09 · AI features, voice and the tutor

**Status (revised 2026-10-28, Phase 5; D-073 to D-082):**

- The tutor panel and its owl character are **built and on by default in authored mode**. Authored mode uses the lesson's own hints, misconception feedback and visual cues, runs entirely on the device and calls no AI service.
- Live AI tutoring and AI voice are **built behind a provider-neutral contract and disabled**. An OpenAI adapter is prepared as the proposed first live provider. It is **not compiled into the app by default**, and live tutoring needs every activation gate below. A configured API key is not an activation decision.
- Nothing has been verified against a live provider. Fixture and live verification are reported separately (docs/phase-5-report.md).
- Offline drafting is a separate, adult-only package in `tools/content-drafting/` that the app never imports.

## Follow-up (2026-10-28): local AI preview, Gemini, and the light lesson design

- **Local AI preview (D-083).** Under `npm run dev` only, a key in `.env.local` (`OPENAI_API_KEY` or `GEMINI_API_KEY`) turns on live tutoring on that computer. The adapters load from `src/tutor/server/adapters.dev.ts` behind a `NODE_ENV === "development"` check. The panel labels it "AI · local preview".
  - If both keys are set, `STUDENT_AI_PROVIDER=openai|gemini` picks one.
  - `STUDENT_AI_ENABLED=false` turns it off.
  - OpenAI also enables push-to-talk and the development microphone policy.
  - Production builds never take this path: the build scan confirms no adapter code reaches them, and every gate below still applies to any deployment.
- **Gemini adapter (D-085).** `adapters/gemini/index.ts` uses plain fetch to `generateContent` with `x-goog-api-key`, a JSON response format with a flat schema narrowed per turn, and mapping to the neutral shape. Blocks, non-STOP finishes, 429 (`retryDelay`), 400/401/403/404 and network errors all map to authored fallback.
  - It is text only (no voice).
  - The default model is `gemini-3.8-flash` (`GEMINI_TUTOR_MODEL`), not live-verified.
  - Gemini's terms bar services likely used by under-18s (OQ-1), so it suits local testing.
  - Both adapters can be compiled in for production with `--provider openai,gemini`, but only the recorded provider may be used, and only its host may appear in the build.
- **Lesson design (D-084).** The lesson and session screens (`.qshell`) use a light, card-based theme inspired by Brilliant:
  - a white question page beside a soft grey canvas with the visual on a white card;
  - a sticky top bar;
  - a bottom action bar with a large black **Check answer** button;
  - coloured feedback bands (green "Correct", red "Not quite");
  - pill buttons.

  The tutor is a chat with an owl header, speech bubbles, a typing indicator, suggestion chips and a composer. "Ask the tutor" is an orange pill in the top bar, and a wrong answer offers "Ask the tutor about it". The roadmap keeps the dark theme. Light-theme token pairs are in `npm run check:contrast`.

## Three modes

| Mode | When | What the student sees | Network |
|---|---|---|---|
| **authored** (default) | Always available; used whenever live tutoring is not fully activated, and as the fallback for any live failure | "Authored learning assistant. Uses this lesson's own hints and visuals. No AI." Five actions; typed and spoken questions say they need the live tutor | None. Turns run in the browser |
| **live** | Only when every activation gate is met, or in the local preview under `next dev` | "AI tutor (OpenAI). Replies are generated by AI and checked against this lesson before you see them." Actions, typed questions and, if enabled, push-to-talk voice | Our own `/api/tutor/*` routes; the server calls the provider. Never browser → vendor |
| **fixture** | Development builds only, with `NOESIS_TUTOR_FIXTURES=1` | "Developer fixture. Not a live tutor: replies are canned test data", plus a banner. Fixture speech is a test tone, labelled as one | Our own routes in `next dev` |

## The tutor panel and the owl

- **Placement.** On screens 1100 px and wider the panel is a third column beside the visual and the question, so it never covers the diagram, the answer or Check. On narrower screens it is a bottom sheet of at most 44 % of the viewport height. The page gains bottom padding and `scroll-padding-bottom`, so scrolling and keyboard focus always stop above the sheet. A demonstration scrolls the visual into view above the sheet. The sheet can be minimised to one row.
- **Actions:** *Help me begin*, *Explain my mistake* (enabled after a wrong answer), *Guide me through the visual*, *Give me the next hint*, and *Read this aloud*. Typed questions and *Use my voice* appear only when the server offers them.
- **The owl** (`src/ui/tutor/OwlTutor.tsx`) is an SVG character built from the supplied artwork in the theme colours and animated with Motion. Each state is driven by a real event:

| State | Driven by |
|---|---|
| listening | the microphone recorder is actually recording |
| speaking | audio is actually playing (Web Audio `onended`, or the device voice's `end` event) |
| waiting | a network turn or transcription is in flight. Authored turns are local, so there is no fake waiting |
| guiding | a tutor demonstration is showing on the visual |
| encouraging | the student just answered correctly |
| unavailable | the last live turn, transcription or playback failed |
| ready | otherwise |

  When several apply, the priority is listening > speaking > waiting > unavailable > encouraging > guiding > ready. Under reduced motion every state is a still pose. *Hide owl* removes the character and is remembered per browser. The owl is decorative (`aria-hidden`). The state is announced as text in a status line.

## What the tutor may see (context)

The browser sends identifiers and untrusted state only: `{templateId, version, seed}`, the action, optional typed text (≤ 1,000 characters), hints shown, phase, its raw answers on this question (≤ 3) and a small widget snapshot. The server (or the browser, in authored mode) rebuilds everything from the shipped manifest (`src/tutor/context.ts`):

- **The question** is re-instantiated from the manifest. An unknown id returns 404 and a changed version returns 409.
- **Attempts are re-checked** with the question's own checker to get their status and misconception tags. A claimed "correct" without a correct answer is ignored. "Exhausted" is accepted only when the lesson itself would allow it (at least one try, or every hint used).
- **The widget snapshot** is validated against the question's widget config. Out-of-range values, locked vectors that moved and unknown agents all fall back to the fresh state, marked untrusted. Highlight targets are enumerated from the validated state, for example `force:v1`, `point:P`, `tangent:P`, `curve:f`, `lane:car`, `endpoint:0:lo` and `side:a`.
- **Hints** contain only those already consumed, plus the next one when the action is *Give me the next hint*.
- **The worked solution and answer** are included only once the question has ended, following the lesson's reveal policy.
- **Excluded:** progress, class, sessions, other questions and other chapters.

## Validated replies and the two tools

Every non-authored reply is validated before it is shown (`src/tutor/guard.ts`). Nothing is streamed to the student.

- **Shape.** The reply must be strictly `{kind: "guidance" | "redirect", say ≤ 600 chars, tools ≤ 2}` with no extra fields.
- **Text.** No links, markup or code. At most five sentences, and it must read as English.
- **Leak check** while the question is open:
  - the answer's own text forms are rejected;
  - so is "the answer is…" phrasing;
  - so is any number above 10 that the student cannot already see.

  This reduces leakage. **It cannot prove that no reply gives the answer away** (for example by describing it in words), which is one reason live tutoring stays behind a red-team review.
- **Tools:**
  - `show_hint {level}` is limited to levels the student has already reached, or the one this turn consumes;
  - `highlight {target}` must name one of the rebuilt targets;
  - a redirect carries no tools;
  - anything else is rejected (no code, SVG, equations, free mutations or submit).
- **Any failure** falls back to the authored reply with a labelled reason: timeout, cancelled, rate limit, provider error, malformed, unauthorised tool, answer leak, unsafe text or ungrounded. The live adapter also asks the provider for a JSON Schema narrowed to this turn's permitted levels and targets.

**In the browser** (`LessonPlayer.applyTutorReply`):

- A reply is applied only if it is for the same question and the same answer state (an epoch of tries, hints and phase) as when it was requested. Otherwise it is set aside with a note. Closing the panel or changing the question aborts the request.
- **Assistance is recorded first, synchronously:**
  - *next hint* dispatches the existing hint action (counted as a hint);
  - a live reply counts as an *explanation* (with tools, a *demonstration*);
  - an authored *Guide me through the visual* with a highlight counts as a *demonstration*;
  - *Help me begin* and *Explain my mistake* repeat the lesson's own orientation and feedback, so they count as no assistance.

  Explanations and demonstrations increment `tutorAssists`, and any of them, like a hint, makes a later correct answer "assisted", never "independent". Opening the panel counts as nothing. The tutor never submits, checks or changes mastery.
- **Demonstrations play on a copy.** The student's widget state is snapshotted, the cues play over the copy, and a banner offers **Back to my work**, which restores the snapshot exactly.

## Provider contract

`src/tutor/contract.ts` has no vendor types and no network code:

```ts
interface TutorProvider {
  id: string; mode: "authored" | "live" | "fixture";
  capabilities: { text; freeText; transcribe; speak; voiceGrant };
  turn(material: TutorMaterial, req: TutorRequest, signal: AbortSignal): Promise<unknown>; // validated by guard.ts
  transcribe?(audio: Blob, signal): Promise<{ text }>;
  speak?(text: string, signal): Promise<{ audio: ArrayBuffer; mimeType; aiGenerated }>;
  createVoiceGrant?(material, signal): Promise<VoiceGrant>; // short-lived, scoped; for a future streaming adapter
}
```

- `AuthoredHintsProvider` (`src/tutor/providers/authored.ts`) gives per-widget guiding questions, the hint ladder and the lesson's misconception feedback.
- The fixture provider (`src/tutor/providers/fixture.ts`) returns labelled canned replies. It also has triggers (`fixture:leak`, `fixture:bad-tool`, `fixture:malformed`, `fixture:slow`, `fixture:delay`, `fixture:error` and `fixture:rate-limit`) that drive every failure path.
- `src/tutor/orchestrator.ts` handles timeouts, cancellation, validation, assistance and fallback; transport is kept separate (`client.ts`, the route handlers).
- The provider-neutral prompt and reply schema are in `src/tutor/prompt.ts`.
- The conformance suite in `tests/unit/tutor-server.test.ts` runs the same checks against the authored provider, the fixture and the OpenAI adapter (mocked network).

## OpenAI adapter (prepared, not active)

`adapters/openai/index.ts` uses plain `fetch` with no SDK, so the dependency check stays meaningful.

- **Text turns** go to the **Responses API** (`POST /v1/responses`) with:
  - `instructions` (tutor rules) and one `input` message with the permitted context;
  - `text.format` set to a **strict** `json_schema` narrowed per turn;
  - `store: false` and `max_output_tokens` ≤ 1200.

  Refusals, incomplete replies and non-JSON become authored fallback.
- **Push-to-talk:**
  - `POST /v1/audio/transcriptions` (multipart, `language=en`);
  - `POST /v1/audio/speech` (mp3, voice `marin`, speaking instructions). Speech is labelled **"AI-generated voice, not a human."**, as OpenAI's usage policies require.
- **Errors** map to fallback reasons and never echo the vendor body or the key:
  - 429 honours `Retry-After` (capped at 300 s);
  - `insufficient_quota` is not retried;
  - 401 and 403 (region) become provider errors;
  - 5xx and network failures also become provider errors;
  - aborts are cancellations.
- **Models are configuration:**

| Variable | Default (from OpenAI docs, 2026-10; **not live-verified**) |
|---|---|
| `OPENAI_TUTOR_MODEL` | `gpt-6-astra` |
| `OPENAI_TRANSCRIBE_MODEL` | `gpt-transcribe` |
| `OPENAI_SPEECH_MODEL` | `gpt-4o-mini-tts` (deprecated by OpenAI; **shuts down 2027-01-06**; its successor is Realtime-only, see limitations) |
| `OPENAI_SPEECH_VOICE` | `marin` |
| `OPENAI_TUTOR_MAX_OUTPUT_TOKENS` | 500 (200–1200) |

- `npm run tutor:verify-openai -- --confirm [--voice]` makes real, billable calls. It runs only when `OPENAI_API_KEY` is in the shell and `--confirm` is passed. Otherwise it reports *pending* and makes no request.

## Activation gates (all required; off by default)

`src/tutor/server/activation.ts` checks, on the server, on every request:

1. **Activation record.** `config/student-ai.json` must have `provider`, `providerDecision` (a decision-log entry) and `privacyReview` (docs/10 sign-off) filled in by a person, and `text: true`. The shipped file has all of these empty.
2. **Server environment.** `STUDENT_AI_ENABLED=true` (exactly), and `STUDENT_AI_PROVIDER` must equal the recorded provider.
3. **Adapter compiled in.** Run `npm run tutor:select-adapter -- --provider openai`, which rewrites `src/tutor/server/adapters.generated.ts`. By default the registry is empty, so the build contains no vendor code or host.
4. **Credentials.** `OPENAI_API_KEY` must be in the server environment. It is read only by the adapter and never sent to the browser, logged or returned.
5. **Voice additionally needs** `"voice": true` in the record and `STUDENT_AI_VOICE=true`. Only then does `next.config.ts` change `Permissions-Policy` from `microphone=()` to `microphone=(self)` (read at build time).

If any gate is missing, the student gets authored mode and every live route returns 404. `GET /api/tutor/features` returns only `{mode, text, voice, providerName}`.

## Server routes

All routes are `force-dynamic`, return `no-store`, rate-limit per client address in memory for 60 s, and log no bodies.

| Route | Purpose | Limits |
|---|---|---|
| `GET /api/tutor/features` | Which mode is active (booleans and a disclosure name) | — |
| `POST /api/tutor/turn` | One validated turn | 32 kB body, 20/min, 15 s provider timeout, cancelled when the browser aborts |
| `POST /api/tutor/transcribe` | Push-to-talk audio → text (not stored) | ≤ 1 MB, ≤ 30 s, audio types only, 10/min |
| `POST /api/tutor/speak` | Speech for **approved** text only. The turn route signs each validated reply (HMAC, per-process secret, 10 min TTL), and the speech route refuses unsigned or altered text | ≤ 600 chars, 10/min |
| `POST /api/tutor/voice-session` | Short-lived scoped grant for a **future** streaming adapter. Grants are refused if expired, longer than 10 min, shaped like a permanent key, or carrying tools other than the two above. The OpenAI adapter does not offer one (501) | — |

CSP is unchanged (`connect-src 'self'`). The browser only talks to our routes, and speech plays through Web Audio `decodeAudioData`, so no `blob:` or `media-src` change is needed.

## Voice pipeline (push-to-talk, transport-neutral)

speech → `/transcribe` → **editable "I heard this" preview** → validated turn → `/speak` → Web Audio playback with captions.

- **Opt-in.** *Use my voice* opens an explainer covering what is recorded, where it goes, that it is not stored, and the 30 s limit. Then *Allow microphone*, then *Push to talk*. The browser permission prompt appears only on the first push.
- **Visible states:** a recording indicator with a timer ("Recording: microphone on"), "Turning your speech into text…", and a speaking badge. The reply text is the caption.
- **Controls:** Stop, Mute, Replay. Starting to talk interrupts playback.
- **Microphone release.** The microphone tracks are stopped when recording stops, when it is cancelled, after 30 s, when the panel closes and when the question changes.
- **Failures** give a clear note, and typing and the buttons keep working. Covered: microphone denied, no device, unsupported browser, blocked by policy, transcription failure, rate limit, playback error and missing credentials (authored mode).
- **Read this aloud** in authored mode uses the device's own *local* speech voices (`localService` only, so no text leaves the device) and is labelled "Read by your device's built-in voice".
- **Future streaming.** WebRTC or WebSocket transport would use `VoiceGrant` from `/voice-session`. The permanent key never reaches the browser.

## Offline content drafting (adult developers only)

`tools/content-drafting/` (see its README) is a separate package with no dependencies. It uses plain `fetch` to Gemini or OpenAI from the **developer's own shell** and has an offline `--fixture` mode.

- `npm --prefix tools/content-drafting run draft -- --template <id> --count 5 [--provider gemini|openai|fixture]` writes `content/drafts/<id>.<time>.draft.json` with `origin: "ai-draft"`, `status: "draft"`, the provider, model and prompt hash. Variations carry only intro, stem, hints and distractor ideas, never answers.
- `run check` rejects any draft that:
  - has a status other than draft, or carries approval fields;
  - has extra fields, such as an answer;
  - has changed placeholders or new numbers;
  - has the wrong hint count, states an answer, or contains links or markup.
- `run verify -- --confirm` makes one live call and checks its shape. Without a key it reports *pending*.
- The tool never edits `content/templates/` or the manifest. A reviewer copies accepted wording into a template, which then goes through `content:validate` and named review (docs/05). `npm run check:no-ai-sdk` fails if `app/` or `src/` imports `tools/`.

## How separation is enforced (`npm run check:no-ai-sdk`)

- There is no AI SDK in the app's dependency tree.
- **Source rules:**
  - `app/` and `src/` never import `tools/`;
  - only the generated registry imports `adapters/`;
  - client components never import server tutor code;
  - no `NEXT_PUBLIC_*` variable names a key, secret, token or vendor;
  - vendor key variables are read only in `adapters/`;
  - `next.config.ts` does not inline env values.
- **Build scan:**
  - the browser bundle (`.next/static`) never contains an AI host or vendor key name;
  - the server bundle may contain a vendor host only when that vendor's adapter is selected **and** the activation record is complete;
  - if `OPENAI_API_KEY` is set in the shell running the check, its value must not appear anywhere in the build.
